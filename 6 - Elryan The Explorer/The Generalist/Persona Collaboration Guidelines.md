# Persona Collaboration Guidelines

This document is the **gridsearch** of how [[Elryan The Explorer]]'s 21 personas collaborate. It defines which personas work together, why, under what conditions, and which active projects belong to each group.

The [[Generalist]] mediates all cross-persona work. When in conflict about ownership or direction, route to [[The Generalist]] → [[The Gatekeeper]] for entity resolution.

## Core Pairs

Pairs are the fundamental collaboration unit — two personas with high natural overlap.

### Commercial & IP Stack

#### [[The Capitalist]] + [[The Gatekeeper]]
**Trigger:** Any commercial venture, contract signing, PIIA, or external IP disclosure.
**Rule:** The Capitalist cannot commit to any external party on matters of IP without The Gatekeeper's review first.
**Projects:** InsightAlly PIIA, all business venture launches, Exhibit A, IP Inventory

#### [[The Capitalist]] + [[The Operator]]
**Trigger:** Any product that requires software, automation, or technical infrastructure.
**Rule:** Capitalist defines the business case; Operator defines the technical path. Neither overrides the other.
**Projects:** Servic.ez/Candoo.co, Life Engine, VELLUM, automation products

#### [[The Capitalist]] + [[The Financer]]
**Trigger:** Business runway decisions, pricing models, burn rate analysis, investment in ventures.
**Rule:** All financial modeling for business ideas routes through The Financer's spreadsheet framework.
**Projects:** The 60 Day Runway, business plan financial sections, Roth IRA vs venture capital tradeoffs

#### [[The Capitalist]] + [[The Website Dealer]]
**Trigger:** Any commercial web presence, client website, or product landing page.
**Rule:** Website Dealer builds; Capitalist approves from business strategy perspective.
**Projects:** Hopefully Abysmal website, Tu Madre Tattoo, coffee-shop templates, Servic.ez frontend

#### [[The Gatekeeper]] + [[The Operator]]
**Trigger:** Open-source software releases, AFPP licensing, code published to public repos.
**Rule:** Every public release needs entity routing (ARX Foundation vs. Hopefully Abysmal) confirmed by Gatekeeper.
**Projects:** ORBUS, VELLUM, Thread Commander, any ARX Foundation code releases

### Technical Infrastructure Stack

#### [[The Operator]] + [[The Website Dealer]]
**Trigger:** Web products that need backend APIs, deployment infrastructure, or server-side systems.
**Rule:** Operator owns the backend; Website Dealer owns the frontend. Handoff at the API boundary.
**Projects:** ARX Homepage, Life Engine web layer, any full-stack product deployments

#### [[The Operator]] + [[The Defender]]
**Trigger:** Any infrastructure work involving security — hardening, VPN, firewall, authentication.
**Rule:** Defender reviews all security decisions; Operator implements. Security is never cut for speed.
**Projects:** RPi Homelab, Biometric Authentication, ARX Foundation sovereignty infrastructure

#### [[The Operator]] + [[The Architect]]
**Trigger:** Systems that have both software and physical/hardware components.
**Rule:** Architect defines physical constraints; Operator defines software architecture. Co-design from the start.
**Projects:** ORBUS (if physical), optical system software, acoustic processing systems

#### [[The Defender]] + [[The Medic]]
**Trigger:** Medical device cybersecurity, embedded systems hardening for healthcare devices.
**Rule:** Defender provides security expertise; Medic provides clinical and regulatory context.
**Projects:** Medical Device Cybersecurity, Autonomous Resuscitation Engine security layer

## Collaboration Rules (Universal)

These rules apply to all multi-persona collaboration:

1. **IP first.** Before any commercial commitment, [[The Gatekeeper]] reviews.
2. **Entity routing is binary.** ARX Foundation = nonprofit/open-source. [[Hopefully Abysmal]] = commercial. Personal = neither.
3. **The Generalist mediates.** When personas conflict, The Generalist adjudicates.
4. **Published: false by default.** No note from any persona goes public without explicit owner instruction.
5. **No stealth names externally.** [[The Gatekeeper]]'s rule applies across all personas in external communication.
6. **Operator implements; others design.** Technical implementation routes to [[The Operator]] or [[The Website Dealer]].
7. **Creostic work is personal.** Never entity-assign philosophical content without explicit owner instruction.
8. **Credentials never in vault.** No API keys, passwords, or `.env` content in any persona's notes.
9. **Cross-persona linking uses WikiLinks.** Use `[[Persona Name]]` syntax for all inter-persona references.
10. **Windows path safety always.** All filenames: ASCII only, under 100 chars, no special characters.
