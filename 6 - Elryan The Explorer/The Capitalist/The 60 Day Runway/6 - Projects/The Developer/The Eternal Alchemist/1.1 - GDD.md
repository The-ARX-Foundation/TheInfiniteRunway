# Main Vision
---

## **1. Gameplay Loop (Roguelike + Alchemy + Exploration)**

- **Core Actions:** Explore rooms → Find “Concept Fragments” → Experiment with combinations → Use creations to influence world state.
    
- **Roguelike Elements:**
    
    - **Procedural Map Generation**: Java handles room layouts, exits, and item spawns.
        
    - **Run-Based Narrative:** Each playthrough generates different “themes” or “archives” (e.g., Science Archive vs Forgotten Myths).
        
    - **Permadeath Option:** Items and fragments discovered in previous runs could be recorded in a “Legacy Codex.”
        
- **Alchemy System:**
    
    - **Fixed core recipes** (to ensure structure).
        
    - **Open-ended combinations** where the LLM generates narrative effects or creative descriptions, but Java validates outcomes (to prevent game-breaking results).
        

---

## **2. LLM Integration — How to Keep It Coherent**

- **LLM Role:**
    
    - **Interpret Creative Inputs:** If the player tries “COMBINE Whisper + Rust,” the LLM decides if the concept is valid, pulling from known recipes or generating a new effect (e.g., _“The whisper turns metallic and shrieks — you’ve created an Echo Blade”_).
        
    - **Narrative Variations:** Generate room descriptions, Archivist dialogue, and lore fragments dynamically.
        
    - **Outcome Suggestions:** When multiple valid item uses exist, LLM chooses from pre-defined effects or invents minor variations.
        
- **Consistency Framework:**
    
    - **Global State:** Java holds the “truth table” for valid recipes, room states, player stats.
        
    - **Room State Context:** Each room maintains its history (items taken, events triggered).
        
    - **Inventory Context:** LLM can “see” your current inventory and adapt narrative (e.g., _“Your Prism flickers as you approach the Gate”_).
        
    - **LLM Filters:** Before accepting an LLM-created item or effect, Java checks **tags**: `destructive? world-breaking? lore-valid?`. Invalid ones are rejected or re-rolled.
        

---

## **3. GUI Vision (Optional Expansion)**

- **Top-Down Explorer Map:**
    
    - Player moves through grid-like rooms (like _Sunless Sea_ or _Other Waters_, but simpler).
        
    - Walls and exits displayed visually; items represented as icons or text labels.
        
- **Alchemy Panel:**
    
    - Drag-and-drop items or type commands (`COMBINE X WITH Y`).
        
    - Results shown via LLM-generated flavor text but validated by Java’s crafting logic.
        

---

## **4. Key Challenges & Solutions**

1. **Infinite LLM Creativity vs Game Stability**
    
    - **Solution:** Treat LLM as a **narrative flavor engine** rather than the primary rules engine. Java defines the “physics” of the Archive, while LLM narrates what’s happening.
        
    - Example: If the player combines random junk, Java checks: _Do these items share an affinity?_ If yes, LLM describes a creative result. If no, return a playful failure response.
        
2. **Replayability Without Chaos**
    
    - Use **seeded procedural generation** for each run. The LLM gets the seed context (themes, tone) to keep the world’s narrative coherent.
        
    - Example: Run seed #451 might lean into “Archive of Stars,” so room descriptions and item names are space-themed.
        
3. **Player Agency**
    
    - Instead of puzzle-gating, give **multiple ways to solve challenges** (burn, illuminate, bribe, create).
        
    - LLM generates narrative responses for different solutions (even emergent ones).
